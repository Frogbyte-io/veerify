Revised model: Workspace → Products → Tools

Structure
  • Workspace (org): people, billing, API keys, Support inboxes and contacts
  • Product: tools (Feedback, Roadmap, Changelog, Marketing), public board, domain
  • No teams. People get access to products directly.
Access
  • Workspace owner/admin: everything, every product
  • Product admin: turn tools on/off and change tool and product settings
  • Product member: use every tool on the product, including Marketing
  • Each product is either open to everyone in the workspace (default) or restricted to invited people

Migration path

1 · Product accessAdd project_member + access mode. Backfill from each product's team (team admin → product admin). Switch requireProjectAccess over.
2 · One switch per toolDrop team_module_settings. Only the product toggle remains, and Support becomes a workspace toggle.
3 · Collapse teamsMove products and support data from extra teams into the workspace's Default team. Keep the old /team/product URLs as redirects.
4 · UIProduct switcher, breadcrumb, settings split, API keys page. Remove team screens.

Steps 1, 2 and 4 make teams invisible without touching the 300+ places that read teamId, because the Default team becomes the workspace's internal data scope. Step 3 is only needed for workspaces that have more than one team. Renaming teamId → workspaceId in code can wait and is optional.
